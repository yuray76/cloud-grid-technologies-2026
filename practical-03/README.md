
# Практична робота №3

## Створення мультитенантного SaaS-застосунку в SAP BTP

### Мета роботи

Ознайомитися з принципами побудови мультитенантних SaaS-застосунків у **SAP Business Technology Platform (SAP BTP)**, навчитися налаштовувати субакаунти Provider і Consumer, перетворювати SAPUI5-застосунок на SaaS, керувати підписками та забезпечувати доступ до застосунку через **SAP Build Work Zone, standard edition**.

### Оцінювання практичної роботи

Максимальна оцінка — **20 балів**.

| Завдання | Бали |
|---|---:|
| Перетворення Hello World на SaaS-застосунок та розгортання в Provider | 10 |
| Створення двох Consumer-субакаунтів і оформлення підписок | 6 |
| Створення двох плиток у SAP Build Work Zone для доступу до SaaS-застосунків | 4 |
| **Разом** | **20** |

---

# 1. Загальна схема виконання практичної роботи

Практична робота складається з трьох основних частин.

## Частина 1. Перетворення Hello World на SaaS-застосунок

Необхідно перетворити застосунок **Hello World**, створений у практичній роботі №1, на мультитенантний SaaS-застосунок та розгорнути його в субакаунті **Provider**.

Для виконання завдання використовуйте інструкцію:

[Приклад перетворення SAPUI5-застосунку з HTML-Rep у SaaS](https://github.com/yuray76/saasDemo)

У результаті SaaS-застосунок повинен бути успішно розгорнутий у Provider та доступний для оформлення підписок іншими субакаунтами.

## Частина 2. Створення Consumer-субакаунтів

Необхідно створити два додаткові субакаунти SAP BTP, наприклад:

- **Consumer 1**
- **Consumer 2**

Для кожного субакаунта необхідно оформити підписку на SaaS-застосунок **Hello World**, розгорнутий у Provider.

У результаті обидва Consumer-субакаунти повинні мати активні підписки на один SaaS-застосунок.

## Частина 3. Налаштування доступу через SAP Build Work Zone

Необхідно створити дві додаткові плитки в **SAP Build Work Zone, standard edition**, які забезпечуватимуть доступ до SaaS-застосунку через відповідні Consumer-субакаунти:

- **Hello World — Consumer 1**
- **Hello World — Consumer 2**

У результаті користувач повинен мати можливість запускати SaaS-застосунок через кожну з двох плиток.

При цьому обидві плитки повинні відкривати один SaaS-застосунок, розгорнутий у Provider, але через різні Consumer-субакаунти.
